먼저 확인할 것

1단계 문의 접수 기록

  1. 기존 기능으로 되는지 확인
  2. 안 되면 새로 만들지 판단
  3. 만들기로 하면 의뢰서

절감 효과가 가장 크다고 확인된 건 아니다. 기존 설정으로 해결될 가능성이 있어 비용을 들이기 전에 먼저 확인할 항목으로 골랐다.

고른 규칙과 만들기로 정한 뒤(구현 담당자 안내)

② 단계 가운데 아직 사람이 하는 첫 단계다.

scorecard build reply-drafts --step 1

담당자 확인
  • 2단계 담당자 확인: 이 단계 결과를 다음으로 넘기기 전에 담당자가 확인한다.
    엔진 문장틀리면 외부에 영향이 있으므로(external) 이 단계 뒤에 사람 게이트를 둔다.
  • 3단계 담당자 서명: 담당자가 최종 확인·서명한다.
    엔진 문장사람이 최종 확인·서명하는 단계이므로(yes) 사람이 하는 것으로 분류.
남는 위험
  • 2단계 답변 초안 쓰기: AI 초안이 틀릴 수 있다. 자동 승인하지 않고 담당자가 확인해 잡는다.
  • 검증 판정이 조건부다. 정확도·누락률은 문턱을 충족하나 불일치 2건이 모두 topic = 환불인 행이므로 조건부.

업무 요약과 입력 기록

입력 원문 보기
문의 메일에 답변을 쓴다. 하루 12통쯤 온다. 지금은 AI가 답변 초안을 쓰고 사람이 고쳐서 보낸다. 답변에는 문의 번호와 처리 안내가 꼭 들어가야 한다. 끝인사도 있어야 한다. 정답 표가 없어 결과를 표처럼 대조할 수 없다. 그래서 메일마다 꼭 들어갈 항목을 표로 적었다. 같은 메일에 사람이 쓴 답변과 AI 답변을 섞어 가림 키를 붙였다. 세 사람이 누가 썼는지 모른 채 1~5점으로 매겼다.
단계 흐름
  1. 문의 접수 기록 규칙 자동화 검토
  2. 답변 초안 쓰기 AI 초안 + 담당자 확인
  3. 답변 확인·발송 담당자 직접 처리
