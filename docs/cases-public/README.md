## 4. 리드 세션 지시

1. **예상 분류 검증**: 1절 50건 중 20건(1, 5, 9, 11, 13, 15, 20, 22, 23, 27, 28, 31, 35, 36, 37, 41, 44, 46, 47, 48)을 `answers.yaml`로 만들어(회사 이름 대신 `case-NN`) 엔진에 넣고, 1절의 예상 분류와 다른 곳을 `docs/cases-public/diff.md`에 적는다. 다른 곳이 빈 곳이다. 이 answers 파일은 `docs/cases-public/answers/`에 두고 `examples/`에는 넣지 않는다.
2. **잠재 빈 곳 처리**: 14~25는 카드를 바로 열지 않는다. 각각 합성 예제 1개를 `spikes/gap-NN/`에 만들어 현재 엔진으로 돌리고, 결과를 `docs/cases-public/gaps.md`에 "막힘 / 틀림 / 문제없음" 중 하나로 적는다. "막힘·틀림"만 카드로 만든다. 문제없음은 닫는다.
3. **우선순위** (확인된 것 먼저, 잠재는 확인 결과가 나온 뒤 끼워 넣는다):
   T-011 판정 → 2 체크리스트·점수표 → 6 혼동행렬 → 8 ②M → 12 수정 기록 → 16 신뢰구간(확인되면) → 22 오류 전파(확인되면) → 1 게이트 종류 → 20 되돌림 → 3·7 결과 대조 → 13 안전망 → 21 규제 플래그 → 14 중첩 → 15 집합·순위 → 10 시간 창 → 23 호출 비용 → 4 MAPE → 19 처리량 → 24 변환 단계 → 17 기준 신뢰도 → 18 저하 추적 → 11 거리 → 25 케이스 목록.
   M2(HTML 스코어카드, 명령 4개)는 6 혼동행렬까지 끝낸 뒤 시작한다.
4. **질문 수 상한**: 19·20·21·23이 모두 질문을 더한다. 단계마다 묻는 질문은 12개를 넘기지 않는다. 넘으면 "고급 질문"으로 묶어 기본값을 두고 `--advanced`에서만 묻는다. 기본 문답은 지금처럼 짧게.
5. **스키마 버전**: 질문·출력이 바뀌는 카드마다 `schema_version`을 올리고 expected migration 규칙(ADR 0004)을 따른다. 여러 카드가 연달아 버전을 올리면 마이그레이션 커밋을 카드마다 따로 둔다.
6. **문서 크기**: 이 파일 외에 사례 설명을 더 두지 않는다. 사례 전문이 필요하면 출처 링크를 연다.
7. **README**: 36번 구조(③ 해석 + ② 기준 검사 + ④ 전문가)를 "권하는 구조"로, 28·47번(규칙으로 끝나는데 AI 사용)을 "과잉 후보" 예로 한 문단씩 쓴다. 회사 이름은 README에서는 빼고 구조만 쓴다.
