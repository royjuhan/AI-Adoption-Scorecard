  • 목적고객 문의에 정책에 맞는 답을 빠짐없이 보내고, 약속이 걸린 답은 담당자 책임으로 보낸다.

다시 넘길 예외고객 번호가 없거나 둘 이상인 메일은 AI 판단으로 넘기고, 담당자가 2단계 초안을 볼 때 함께 확인한다.
기존 기능으로 해결메일 도구의 분류·전달 규칙으로 모으기까지 되는지 먼저 본다.
새로 개발고객 번호 찾기와 기록 조회 연결.
비용·부담 검토메일과 기록 시스템을 잇는 유지보수가 든다. 호출은 문의마다 한 번이다. 실제로 일이 줄어드는지는 재지 않았다.

검증 방법과 역할 전환 조건

제안이 효과적인지는 실제 자료 시험(check)으로 확인한다. 역할은 아래 근거가 모인 뒤에만 바꾼다. AI의 자신감만으로 맡기는 범위를 넓히지 않는다.

  1. 2단계 의도 해석과 답변 초안 AI 초안 + 담당자 확인 → 규칙 자동화 검토
    바꾸는 조건자주 오는 문의가 몇 가지 양식으로 묶이고, 양식 답을 담당자가 거의 고치지 않는다.
    필요한 근거문의 유형별 표본, 담당자 수정 기록, 양식 답과 담당자 답을 대조한 check 결과.
  2. 1단계 문의 모으기와 기록 붙이기 규칙 자동화 검토 → AI 초안 + 담당자 확인
    바꾸는 조건고객 번호가 없는 메일이 늘어 규칙으로 고객을 찾지 못하는 건이 많아진다.
    필요한 근거규칙으로 붙이지 못한 메일 수와 그 사유 기록(운영 데이터).

지금 할 일
  1. 단계마다 맞는지 확인한다(맞음/바꾸기): 2, 4단계.
개선을 진행하려면
  1. 먼저 확인할 것부터 본다. 기존 기능으로 되면 끝, 안 되면 새로 만들지 판단하고, 만들기로 하면 의뢰서를 낸다.
  2. AI가 가정한 답을 확인한다: 2단계 판단 기준을 글로 쓸 수 있나.
  3. 말하지 않아 기본값으로 둔 답을 확인한다: 1단계 예외 비율; 2단계 예외 비율; 3단계 예외 비율; 4단계 예외 비율.
실제 효과까지 검증하려면(선택)
  1. 실제 효과까지 보려면 사람이 만든 결과와 AI 적용 결과를 한 벌씩 준비해 비교한다.
  2. 실제 검증 때 무엇을 오류로 셀지 먼저 정한다.
  3. 개선 전후를 비교하려면 단계별 건당 시간을 잰다: 1, 2, 3, 4단계.
구현·검증 담당자 안내
  1. 기준 자료(사람이 만든 결과)는 reference/, 결과 자료(AI 적용 후)는 candidate/에 넣고 case.yaml에 inputs·compare·thresholds를 적은 뒤 scorecard check를 돌린다.
  2. 단계 확인 결과는 확인 파일(--review)로 open에 넣는다.
  3. 만들기로 정하면 scorecard build ai-roles --step 1 명령으로 의뢰서 번들을 쓴다. 내보내기 전에 export-check.md에 사람이 확인을 적는다.
