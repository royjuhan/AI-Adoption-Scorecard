1단계를 만들까요?

정상 신호 구간 선택. ② 단계 가운데 아직 사람이 하는 첫 단계다.

= scorecard build table-compare (의뢰서 번들, M2-4)

사람 게이트와 남는 위험
  • 2단계 ④ 예외 검토: 판단 기준을 일부만 글로 쓸 수 있으므로(partial) 예외 건은 사람이 검토한다.
  • 4단계 ④ 게이트: 틀리면 외부에 영향이 있으므로(external) 이 단계 뒤에 사람 게이트를 둔다.
  • 검증 판정이 조건부다. 정확도·누락률은 문턱을 충족하나 불일치 3건이 모두 signal_type = irregular인 행이므로 조건부.

일치 27건 중 4건은 허용오차 안의 차이. 누락률 3.3%.
판정조건부 정확도·누락률은 문턱을 충족하나 불일치 3건이 모두 signal_type = irregular인 행이므로 조건부.
문턱: 정확도 85% 이상, 누락률 5% 이하
  • ACCURACY 충족 정확도 90.0%(27/30)가 문턱 85% 이상이다.
  • MISSING 충족 누락률 3.3%(1/30)가 문턱 5% 이하다.
  • UNEXPLAINED 사람 확인 전 검토할 항목 4건(불일치 3건, 추가 행 1건)이 설명되는지 사람이 아직 보지 않았다.
  • TIME 쓰지 않음 시간 조건을 쓰지 않는다(time_must_drop: false).
  • FOCUS 몰림 불일치 3건이 모두 signal_type = irregular인 행이다(irregular 12행 중 3행, 다른 값 18행 중 0행).

업무 개요와 입력 기록

사용자가 말한 그대로(intake.md)
매주 센서 로그 파일을 30개쯤 받는다. 로그마다 그래프를 보고 신호가 안정된 구간을 하나 고른다. 구간의 시작 위치와 길이를 적고, 그 구간의 평균값을 낸다. 신호가 불규칙한 로그는 구간을 고르기 어렵다. 오래 걸리고, 사람마다 고르는 곳이 다르다. 고른 구간과 평균값은 정해진 결과표에 채워서 다른 팀에 보낸다. 같은 로그를 AI에게 주고 구간과 평균을 받아 본 결과가 있다. 사람이 만든 결과표와 맞는지 비교하고 싶다.
단계 흐름
  1. 정상 신호 구간 선택 ② 규칙 SW
  2. 불규칙 신호 구간 선택 ② 규칙 SW
  3. 구간 평균 계산 ② 규칙 SW
  4. 결과표 채우기 ② 규칙 SW
