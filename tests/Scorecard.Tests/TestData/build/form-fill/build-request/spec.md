# 제작 의뢰서: form-fill 2단계

- 업무: 고정 양식 주문서를 받아 품목·수량을 집계하고 주간 보고서를 만든다
- 만들 단계: 2단계 주문서 양식 읽기
- 담당: ②. 규칙 기반 소프트웨어로 만든다. 실행 시 AI를 부르지 않는다.
- 판단: 규칙 트리 ② `ELSE`. 규칙 의견 ② `ELSE`.
- 근거: 판단 기준을 글로 쓸 수 있고(yes), 입력이 고정 양식이며(fixed_form), 매주 반복되므로 규칙 기반 소프트웨어로 분류.

## 입력 → 처리 → 출력

- 입력: 형태 `fixed_form`, 한 번에 20건, 빈도 `weekly`.
- 처리: 근거 문장의 판단을 코드 규칙으로 옮긴다(아래 규칙 초안).
- 출력: `io-schema.json`의 열 3개. 키 `order_id`.

## 규칙 초안

- `item`: 글자. 앞뒤 공백을 뗀 뒤 정확히 같아야 한다.
- `quantity`: 숫자. 허용 오차 0(절대).
- 기본값을 쓴 답: `minutes_per_item`. 제작 전에 확인한다.
- AI가 추정한 답: 없다.

## 예외 처리

- 예외·이상 건 비율: 5%.
- 예외 검토 행이 없다. 규칙에 맞지 않는 건은 결과에 넣지 않고 멈춘 뒤 사람에게 넘긴다.

## 사람 게이트

- 이 단계 뒤 사람 게이트가 없다.
- 업무의 다른 사람 확인: 4단계 주간 보고서 만들기(`human_gate`).

## 실행 조건

- 실행 시 AI·네트워크·외부 프로세스를 쓰지 않는다.
- 같은 입력이면 같은 결과다. 난수·현재 시각을 결과에 쓰지 않는다.
- 입력 파일은 읽기만 한다. 출력은 새 폴더에 쓴다.
