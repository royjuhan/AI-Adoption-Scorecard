# 제작 의뢰서: signoff-final 3단계

- 업무: 기록 파일에서 기준 구간을 골라 값을 내고, 보고서를 써서 사람이 서명해 제출한다
- 만들 단계: 3단계 기준 구간 고르기(흔들린 기록)
- 담당: ②. 규칙 기반 소프트웨어로 만든다. 실행 시 AI를 부르지 않는다.
- 판단: 규칙 트리 ② `ELSE`. 규칙 의견 ② `ELSE`.
- 근거: 판단 기준을 일부만 글로 쓸 수 있고(partial), 입력이 표 형식이며(table), 매주 반복되므로 규칙 기반 소프트웨어로 분류.

## 입력 → 처리 → 출력

- 입력: 형태 `table`, 한 번에 6건, 빈도 `weekly`.
- 처리: 근거 문장의 판단을 코드 규칙으로 옮긴다(아래 규칙 초안).
- 출력: `io-schema.json`의 열 5개. 키 `record_id`.

## 규칙 초안

- `range_start`: 숫자. 허용 오차 0(절대).
- `range_end`: 숫자. 허용 오차 0(절대).
- `range_avg`: 숫자. 허용 오차 1.0%(기준 값 기준).
- 기본값을 쓴 답: `minutes_per_item`. 제작 전에 확인한다.
- AI가 추정한 답: 없다.

## 예외 처리

- 예외·이상 건 비율: 50%.
- 예외 검토 ④: 판단 기준을 일부만 글로 쓸 수 있으므로(partial) 예외 건은 사람이 검토한다.

## 사람 게이트

- 이 단계 뒤 사람 게이트가 없다.
- 업무의 다른 사람 확인: 6단계 결과 해석 문장 쓰기(`human_gate`), 7단계 최종 확인·서명·제출(`signoff`).

## 실행 조건

- 실행 시 AI·네트워크·외부 프로세스를 쓰지 않는다.
- 같은 입력이면 같은 결과다. 난수·현재 시각을 결과에 쓰지 않는다.
- 입력 파일은 읽기만 한다. 출력은 새 폴더에 쓴다.
