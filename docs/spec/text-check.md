# text-check (문장 결과 검증)

- 지금 동작만 적는다. 표·예시 블록·예제 파일·SHA-256 줄은 `docs/spec/data/text-check.md`에 있다. 절 번호가 같다. 테스트와 oracle이 그 파일을 읽는다.
- 결정 근거: ADR 0009(두 길), ADR 0004·0005·0008·0010. 바뀐 기록은 git 기록에 있다.
- 문장 결과: 정답 표가 없는 결과(요약, 답변 초안, 보고서 문장). 결과 자료의 한 칸에 문장이 들어 있다.
- 길 1 체크리스트 대조: 결과 문장마다 꼭 들어갈 항목이 있는지 문자열 규칙으로 본다(4.2).
- 길 2 가림 점수표: 사람이 AI 결과와 사람 결과를 누가 썼는지 모르고 매긴 점수(4.3). 엔진은 모으기만 한다.
- 가림 키: 채점자가 보는 결과 이름. 출처 표: 가림 키 → 건·출처(`ai`·`human`). 채점자에게 주지 않는다.
- "표 대조" = 대조가 `measured`(compare 필드 또는 체크리스트)이고 점수표가 있음. "점수표만" = 대조가 미검증이고 점수표가 있음.

## 1. 범위

- 범위 밖: 결과 문장의 뜻 읽기(엔진에 자연어 처리가 없다), 채점자 사이 일치도, 표본 크기·신뢰 구간, 가림 키 순서로 출처 짐작, 사람 결과 문장 원문, 명령 인자와 화면 문구.

## 2. 입력

- `case.yaml`의 최상위 키 둘: `checklist`(길 1), `scores`(길 2). 둘 다 선택이다. 둘 다 없으면 `metrics.md`·`judgment.md` 그대로다.
- 길 1 자료: `inputs` 그대로다. 기준 자료는 건 목록과 건마다 들어갈 값, 결과 자료는 AI 결과 문장이 한 칸에 든 표다.
- 길 2 자료: 점수표 CSV(채점자가 채움)와 출처 표 CSV(채점을 준비한 사람이 가짐).
- CSV 읽기와 파일 찾기는 `metrics.md` 4.1·4.2 그대로다. 문장 칸에 `,`·줄바꿈이 있으면 따옴표로 감싼다.

## 3. 출력

### 3.1 metrics.json에 더하는 속성

- 설정했을 때만 쓴다. `checklist`가 없으면 `compare.checklist`·`items[].missing_items`가 없고, `scores`가 없으면 최상위 `scores`가 없다. 그래서 예제 4종 `expected/metrics.json`은 그대로다.
- 모양 블록과 새 속성 표는 데이터 3.1이다.
- 자리: `compare.checklist`는 `fields` 뒤·`items` 앞. `missing_items`는 항목의 `differences` 뒤. `scores`는 `compare` 뒤(최상위 마지막).
- 가림 발견(`findings[]`)의 속성은 `rule`, `file`, `line`, `value`다.
- 쓰지 않는 것: 문장 원문, 출처 표의 행 목록, 채점자별 건별 점수.

### 3.2 judgment.json에 더하는 속성

- `scores`가 있을 때만: `thresholds.score_gap_max`(문턱 셋 뒤), `checks`의 `SCORE`(여섯째). 표는 데이터 3.2.
- 점수표만이면 `checks`는 `TIME`, `SCORE` 둘이다. `checklist`는 대조 셈으로 들어가 판정 모양을 바꾸지 않는다.
- `rule` `NOT_VERIFIED`가 `verdict` `conditional`과 같이 나올 수 있다(5.3). 판정은 `verdict`가 정한다.

### 3.3 바이트 규칙과 `schema_version`

- 바이트 규칙은 `metrics.md` 3.3·`judgment.md` 3.3 그대로다. 평균은 `decimal` 글(`3.86`, `4.00`)이다.
- `schema_version`은 metrics.json 1, judgment.json 2 그대로다(ADR 0008 결정 1: 새로 받는 입력 모양만 출력이 바뀌었다).

### 3.4 명령과 AI용 입구

- `compare --json` = metrics.json, `judge --json` = judgment.json 그대로다. 새 명령은 없다.
- 종료 코드: 4.5 오류는 2. 가림이 깨진 것(`revealed`)은 오류가 아니라 판정이다(0).

## 4. 규칙

### 4.1 `case.yaml` 키

- 키 표와 파서 장면 표는 데이터 4.1. 오류 코드는 `case-schema.md` 4.9의 17개 그대로다.
- 단계 질문은 늘지 않는다(10개). 두 길은 케이스 수준 키다.
- 문구·열 이름은 사용자 낱말 그대로 쓴다. 정규식은 쓰지 않는다.
- 위치는 `case-schema.md` 4.9 규칙대로다. `range` 메시지 모양은 `범위 밖이다 (<범위>): <값>`이다.

### 4.2 체크리스트 대조

체크리스트는 대조의 한 종류다. `inputs`의 키로 기준 행과 결과 행을 짝짓고, 짝지은 결과 행마다 항목을 본다.

1. 열: 기준 파일마다 `column` 항목의 열이, 결과 파일마다 `checklist.text` 열이 머리 행에 꼭 한 번 있어야 한다(`column`, `duplicate-column`). 찾는 순서는 키 열 → `compare` 필드 → `inputs.group` → 체크리스트 열이다.
2. 글: 정규화(`metrics.md` 4.6) 뒤의 글이다. 비교 전에 문장·기준 칸·`any` 문구 모두 공백 글자가 이어진 곳을 U+0020 하나로 접고 앞뒤를 뗀다.
3. 있다: 접은 문구가 접은 문장의 부분 문자열이면(서수) `found`. 대소문자·NFC·전각을 맞추지 않는다.
4. `column` 항목: 그 기준 행의 칸이 문구다. 칸이 비면 그 행에는 요구하지 않는다(`skipped`, 셈에 들지 않음).
5. `any` 항목: 문구 가운데 하나라도 있으면 있다.
6. 빠진 항목(`absent`)이 하나라도 있으면 그 기준 항목은 값 불일치다. `compare` 필드와 같이 쓰면 둘 중 하나라도 걸리면 값 불일치다. 셈·정확도는 `metrics.md` 그대로다.
7. 결과 쪽 중복: 대표 행의 빠진 항목은 기준 항목에, 둘째 이후 행의 빠진 항목은 `duplicate` 항목에 적는다.
8. 항목 셈(`entries[]`)은 기준에 키가 있는 결과 행마다 센다. `required` = `found` + `absent`.
9. 한계: 부분 문자열이라 `q397`은 `q3970` 안에서도 있다. 사용자가 문구를 길게 쓰면 줄어든다.
10. 확인할 것이 없는 행: `compare` 필드가 없고, `any` 항목이 없고, 그 기준 행의 `column` 칸이 모두 비면 `no-check` 오류다. 기준 행마다 본다.

- 맞추기 표와 체크리스트 장면 표는 데이터 4.2.

### 4.3 가림 점수표

- 파일 표는 데이터 4.3. 열 이름은 정해져 있다(서수, 정규화 뒤). 다른 열이 있어도 된다. 그 칸은 채점자에게 보이는 표시로 본다(4.4).
- 채점자가 채우는 다른 값(하위 점수, 의견)은 점수표 밖 다른 파일에 둔다.

1. 출처 표: 가림 키는 쪽 전체에서 하나씩(`duplicate-key`). 출처는 `ai`·`human`(`source`). 건마다 `ai` 하나, `human` 하나(`pair`).
2. 점수표: 점수 칸은 정규화한 값이 정수 글 `0` 또는 `[1-9][0-9]*`이고 `min` 이상 `max` 이하다(`score`). 가림 키는 출처 표에 있어야 하고 건이 같아야 한다(`blind`). 대조가 `measured`면 출처 표의 건은 기준 자료의 키여야 한다(`blind`).
3. 빠진 점수: 출처 표의 가림 키마다 점수가 하나 이상 있어야 한다(`blind`).
4. 집계: 출처마다 결과 수, 점수 수, 합, 평균, 분포. 평균은 `hundredths = (2 × 합 × 100 + 수) div (2 × 수)`, 늘 두 자리다. 평균 표는 데이터 4.3.
5. 건마다 비교(`paired`): AI 점수 합 × 사람 점수 수와 사람 점수 합 × AI 점수 수를 견준다. `better`, `same`, `worse`.
6. 채점자별(`by_rater`): 채점자마다 출처별 점수 수와 평균. 없으면 null.
7. 판정 비교는 합·수 셈으로 한다.
8. 순서: 파일은 경로 서수, 행은 파일 → 줄. `raters`는 서수. 출처는 `ai` → `human`.

### 4.4 가림 확인

- 엔진은 점수표와 출처 표 글만 본다. 출처 낱말(`source`, `ai`, `human`)과 표시 몰림(`source_pattern`)을 찾는다. 하나라도 있으면 `blind.status` = `revealed`이고 판정이 보류다. 오류가 아니다.
- 가림 규칙 표는 데이터 4.4. 순서: 규칙 → 파일 경로 서수 → 줄 → 칸 순서.
- 출처 낱말: ASCII 소문자로 바꾼 뒤 본다. 조각은 이어진 ASCII 영문자 또는 숫자다. 조각 하나가 `ai`·`human`이면 걸린다.
- 표시: 글 그대로, 틀(ASCII 숫자 묶음을 지운 글), 첫 글자, 끝 글자(숫자가 아닐 때만). 글자는 코드 포인트 하나다. 가림 키에서는 꼴·글자 수(UTF-16)·글자 종류·숫자 줄과 작은 쪽도 본다. 표는 데이터 4.4.
- 보는 곳 셋: 결과의 가림 키, 점수표 행의 다른 열 칸, 점수표 행이 든 파일.
- 건이 갈림: 키는 그 건의 두 가림 키를 견준다. 열·파일은 두 출처를 모두 매긴 채점자의 행만 본다.
- 몰림: 표시마다 AI 쪽 a, 사람 쪽 h, 센 건 N. c = a + h, M = max, m = min. c ≥ 8, 12 × m ≤ c, 4 × M ≥ N이면 걸린다. 문턱 표와 예 표는 데이터 4.4. N ≤ 7이면 걸리지 않는다.
- 발견: 걸린 표시마다 그 표시가 있는 첫 칸 하나다.
- 점수 자료 장면 표는 데이터 4.4.

### 4.5 오류

- `CaseError` 그대로다. 문자열 형식·`Source`·`Path` 규칙은 `metrics.md` 4.7·3.4와 같다. 오류가 하나라도 있으면 metrics.json·judgment.json이 없다.
- 점수 오류 코드 표와 체크리스트 코드 표(`no-check`)는 데이터 4.5. `metrics.md` 4.7의 코드는 같은 뜻으로 점수 파일에도 쓴다.
- 파일이 정해지기 전 오류의 `Source`는 `case.yaml`, 경로는 `scores.sheet`·`scores.sources`다.
- 순서: 대조 쪽 → 출처 표 → 점수표 → 점수가 없는 키.
- 대조 쪽 오류가 있으면 기준 자료와 맞춰 보는 `blind` 검사를 하지 않는다. 출처 표를 끝까지 읽지 못했으면 점수표와 맞춰 보는 검사를 하지 않는다.
- 사람 자료의 결함은 오류로 멈춘다. AI 결과의 결함은 셈과 판정이다.

### 4.6 결정론·원본 불변·G1·G2·G3

- 모든 비교는 서수, 숫자는 정수와 `decimal`·`InvariantCulture`다. 파일은 읽기만 한다.
- CSV를 CRLF·CR·BOM·따옴표·끝 줄바꿈 없음·끝 빈 행·칸 앞뒤 공백으로 바꿔도 바이트가 같다.
- 한글 문장·평균 글이 출력에 들어가므로 G2가 문화권(R4)을 본다.

## 5. 판정 (`judgment.md` 4절에 더한다)

- 점수표가 있을 때만 아래 행이 더해진다. 없으면 판정 바이트가 그대로다. 체크리스트는 대조 셈으로 판정에 닿는다.

### 5.1 점수 문턱 기본값

- `score_gap_max`가 없으면 데이터 5.1 표의 값을 쓰고 `defaults`에 적는다(`judgment.md` 4.2 순서 뒤).
- 점수표만이면 `defaults`에는 이 길이 읽는 문턱(`time_must_drop`, `score_gap_max`)만 적는다.

### 5.2 확인 `SCORE`

- 표는 데이터 5.2. 셈은 정수와 `decimal`이다. 같으면 `met`이다. 사람 쪽만 높은지(한쪽)만 본다.
- 문장 값: `{findings}` = 발견 수, `{ai_mean}`·`{human_mean}` = 평균 글, `{ai_ratings}`·`{human_ratings}` = 점수 수, `{score_gap_max}` = 쓴 문턱 글.
- 값이 0이면 문턱 0 문장(데이터 5.2 둘째 표)을 쓴다. 문장의 "낮다"는 셈이 기준이다.

### 5.3 판정 행

- 표는 데이터 5.3. "자리"는 `judgment.md` 4.3의 순서다.
- 점수표만: 대조 확인 넷이 없다. 판정은 `SCORE` 두 행 → 대조할 열 없음 → `TIME` → `PASS` 순서다.
- 대조할 열 없음: `inputs`는 있는데 `compare`·`checklist`가 없으면 통과가 아니라 조건부이고 `add_compare`가 나온다. `inputs`가 없으면 이 행에 걸리지 않는다.
- 표 대조 + 점수표: `checks`는 다섯 + `SCORE`. 판정은 순서 2~4 → `SCORE` 두 행 → 순서 5~8이다.
- 점수표만이면서 사람 입력을 받으면 `ArgumentException`이다.

### 5.4 읽은 문턱

- 표는 데이터 5.4. 점수표가 없으면 `judgment.md` 4.6 그대로다.

### 5.5 다음 할 일

- 표는 데이터 5.5. 자리는 `add_group` 뒤, `confirm_thresholds` 앞이다.
- 점수표만이면 대조 쪽 할 일(`add_data`, `review_items`, `add_group`)은 나오지 않는다.

### 5.6 정의와 대조 결과

- `checklist`가 있으면 대조 결과가 `measured`이고 `compare.checklist.text`·항목 이름(순서)이 정의와 같아야 한다. 없으면 대조 결과에 `checklist`가 없어야 한다.
- 점수표 집계는 정의에 `scores`가 있을 때만 있어야 한다. 아니면 `ArgumentException`이다.

## 6. 예시

- 판정 장면 표와 장면 글머리(6.1), `score-only` 케이스(6.2)는 데이터 6절이다. `score-only`는 reply-drafts의 `scores/` 두 파일과 그 `case.yaml`로 만든다. 대조는 미검증 `no_inputs`다.
- reply-drafts 결과: 체크리스트 12건 중 `d03`(`action` 빠짐), `d12`(`ticket` 빠짐)가 값 불일치다. 둘 다 `topic = 환불`이다. 정확도 83.3%. 점수 AI 평균 3.86, 사람 4.19, 차이가 문턱 0.5 안이라 `met`. 판정은 조건부 `FOCUS`다.

## 7. 예제 reply-drafts

- 새 예제 표와 예제 파일 표는 데이터 7.1. 블록은 파일 표 순서로 데이터 7.3·7.4에 있다. 파일은 블록과 바이트까지 같다.
- 자료 파일은 합성 생성기가 만든다. `case.yaml`·`answers.yaml`·`intake.md`는 손으로 쓴 글이다. expected 블록은 oracle이 낸 바이트이고 Core가 맞춘다.
- 생성기는 `synthetic-examples.md` 4.2의 SplitMix64와 `NextBelow`를 쓴다. 계획 표는 데이터 7.2. 뽑는 순서:
  1. 유형: 행마다 `유형[NextBelow(3)]`.
  2. 문의 번호: 행마다.
  3. 행마다 인사 `NextBelow(2)`, 덧붙임 `NextBelow(3)`, 끝인사 `NextBelow(2)`.
  4. 빠뜨릴 행: `환불` 행 목록에서 `NextBelow(수)`번째가 번호를, 그 행을 뺀 목록에서 `NextBelow(수)`번째가 안내를 빠뜨린다. 목록이 2보다 짧으면 예외.
  5. 결과 행 순서: Fisher–Yates(i = 11..1).
  6. 가림 키: (행, `ai`), (행, `human`) 24개를 5와 같이 섞는다. k번째가 `b` + (k + 1) 2자리다.
  7. 점수: 채점자 순서 → 가림 키 순서. AI는 `AI 점수[NextBelow(4)]`(빠뜨린 행이면 감점), 사람은 `사람 점수[NextBelow(4)]`.
- 문장 = 인사, 번호 문장, 안내 문장, 덧붙임, 끝인사를 공백 하나로 잇는다. 파일 머리 행은 데이터 7.2 글머리다.
- CSV 바이트: UTF-8(BOM 없음), LF, 끝 LF, 따옴표 없음. 칸은 비지 않고 `,`·`"`·줄바꿈·탭이 없다.
- 시드는 조건(세 유형 모두 2행 이상, AI 평균 < 사람 평균, 차이 0.5 이하)을 만족하는 가장 작은 값이다.
