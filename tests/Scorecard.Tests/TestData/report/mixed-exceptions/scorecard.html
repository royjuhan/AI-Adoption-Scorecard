1단계를 만들까요?

메일 접수 기록. ② 단계 가운데 아직 사람이 하는 첫 단계다.

= scorecard build mixed-exceptions (의뢰서 번들, M2-4)

사람 게이트와 남는 위험
  • 3단계 ④ 게이트: 틀리면 외부에 영향이 있으므로(external) 이 단계 뒤에 사람 게이트를 둔다.
  • 2단계 문의 유형 분류: 실행 시 AI 보조다. 자동 승인하지 않고 사람이 확인한다.
  • 3단계 답변 초안 쓰기: 실행 시 AI 보조다. 자동 승인하지 않고 사람이 확인한다.

검증

대조할 자료가 없다(미검증).

판정미검증 검증 자료(case.yaml inputs)가 없어 미검증.
문턱: 정확도 95% 이상, 누락률 2% 이하

다음 할 일

  1. 기준 자료(사람이 만든 결과)를 reference/에, 결과 자료(AI 적용 후 결과)를 candidate/에 넣고 case.yaml inputs에 파일 패턴과 키 열을 적는다.
  2. case.yaml compare에 대조할 열과 허용 오차를 적는다.
  3. 건당 처리 시간·검토 시간과 적용 전 시간(분)을 잰다.
  4. 문턱에 기본값을 썼다(accuracy_min 95, missing_max 2, time_must_drop true). 맞는지 확인하고 case.yaml thresholds에 적는다.
  5. 건당 시간(minutes_per_item)을 잰다: 1, 2, 3, 4단계.
  6. 단계 확인(맞음/바꾸기)이 아직 없다: 1, 2, 3, 4단계. 확인 파일을 --review로 넣는다.

업무 개요와 입력 기록

사용자가 말한 그대로(intake.md)
문의가 메일로 하루 15통쯤 온다. 형식이 정해져 있지 않다. 메일이 오면 접수 기록을 남긴다. 그다음 문의 유형을 나누고 답변 초안을 쓴다. 유형이 애매한 메일이 꽤 있다. 답변은 밖으로 나가므로 틀리면 곤란하다. 처리가 끝나면 결과를 표에 기록한다. 아직 AI를 써 보지 않았다. 비교할 결과 자료도 없다.
단계 흐름
  1. 메일 접수 기록 ② 규칙 SW
  2. 문의 유형 분류 ③ AI 보조
  3. 답변 초안 쓰기 ③ AI 보조
  4. 처리 결과 기록 ② 규칙 SW
