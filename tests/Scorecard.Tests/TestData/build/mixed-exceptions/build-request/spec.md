# 제작 의뢰서: mixed-exceptions 1단계

- 업무: 자유 형식 메일을 접수해 분류하고 답변 초안을 쓴다
- 만들 단계: 1단계 메일 접수 기록
- 담당: ②. 규칙 기반 소프트웨어로 만든다. 실행 시 AI를 부르지 않는다.
- 판단: 규칙 트리 ② `ELSE`. 규칙 의견 ② `ELSE`.
- 근거: 판단 기준을 글로 쓸 수 있고(yes), 입력이 고정 양식이며(fixed_form), 매일 반복되므로 규칙 기반 소프트웨어로 분류.

## 입력 → 처리 → 출력

- 입력: 형태 `fixed_form`, 한 번에 15건, 빈도 `daily`.
- 처리: 근거 문장의 판단을 코드 규칙으로 옮긴다(아래 규칙 초안).
- 출력: 열이 정해지지 않았다. case.yaml에 inputs를 적고 다시 만든다.

## 규칙 초안

- 비교 열이 없다. 규칙은 제작 환경의 스펙 승인 때 정한다.
- 기본값을 쓴 답: `minutes_per_item`. 제작 전에 확인한다.
- AI가 추정한 답: 없다.

## 예외 처리

- 예외·이상 건 비율: 5%.
- 예외 검토 행이 없다. 규칙에 맞지 않는 건은 결과에 넣지 않고 멈춘 뒤 사람에게 넘긴다.

## 사람 게이트

- 이 단계 뒤 사람 게이트가 없다.
- 업무의 다른 사람 확인: 3단계 답변 초안 쓰기(`human_gate`).

## 실행 조건

- 실행 시 AI·네트워크·외부 프로세스를 쓰지 않는다.
- 같은 입력이면 같은 결과다. 난수·현재 시각을 결과에 쓰지 않는다.
- 입력 파일은 읽기만 한다. 출력은 새 폴더에 쓴다.
